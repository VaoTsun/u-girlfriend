## 2026-10-24 — «Насущное» как граф: зависимости много-ко-многим (DAG)

**Запрос:** «Нужна иерархия работ, где зависимости не один-ко-многим, а
много-ко-многим: одна работа может ждать несколько предыдущих, а одна
предыдущая открывать несколько следующих (камин и печь оба ждут “нанести
кирпич”). Какой самый короткий и экономичный способ?» → «Делай».

**Выбор структуры (и почему):** таблица связей — self-referencing
many-to-many, т.е. граф (DAG), а не дерево:

```sql
dev.nasushchnoe_dep(task_i, dep_i)   -- (5,3) = «5 нельзя начинать, пока не сделана 3»
primary key (task_i, dep_i), check (task_i <> dep_i),
оба FK references dev.nasushchnoe(i) on delete cascade
```
- Одна колонка `parent_i` не годится: 1:N, у камина два родителя.
- `deps int[]` в основной таблице короче на один ALTER, но нет FK: удалил
  дело — в массивах остаются битые id. Поэтому join-таблица.
- Уровни/порядок не материализуем: дерево считается на лету (`nsTree.js`),
  иначе пришлось бы пересчитывать всю ветку после каждой правки.

**Сделано:**
- DDL: `sql/dev.nasushchnoe_dep.create.sql` (применён на проде, PG 16.11),
  индекс по `dep_i` («кто ждёт меня»). DDL в `SQL_ALLOWLIST` не входит —
  через `/sql` не отдаётся (проверено: 400).
- SQL: `dep.ins` — **вставка с защитой от кольца** (рекурсивный обход предков
  + `on conflict do nothing`, в ответе `allowed`/`inserted`, чтобы бот объяснил
  отказ), `dep.del`, `dep.list`; `list` теперь отдаёт `deps`, `unlocks`,
  `blocked_by`.
- Бот: «5 ждёт 3» / «5 зависит от 3» / «связь 5 ждёт 3», «5 больше не ждёт 3»,
  «развяжи 5 3», «что ждёт 5», «что откроется после 3», «дерево»; «список» —
  деревом с отступами и ⛔ «ждёт #…»; после «сделано N» бот пишет, что
  расблокировалось. Слово «насущное» — в любом окончании (см. 2026-10-21).
- Страница `/nas.html`: дерево с отступами, колонки «Ждёт» (с ✖ для снятия) и
  «Откроет», форма «Дело № … ждёт № …», ⛔ у заблокированных. Раскладку в дерево
  считает `u-barn/nsTree.js` — **один код на страницу и бота**.
- Скилл `skills/nasushchnoe`: `-List` показывает «(ждёт: #3, #7)», в SKILL.md
  описан граф; `knowledge/voltage-db.md` перегенерирован (`tools/dbdoc.js`).

**Грабли (важно):**
- Кольцо в PG декларативно не запретить: проверка живёт в самом INSERT
  (`with recursive anc … where not exists (select 1 from anc where i = $1)`).
  Плюс `nsTree.js` всё равно не зацикливается: обход с `seen`, лишние строки
  выводятся корнями.
- Задача с двумя родителями в дереве показывается **один раз** (под первым по
  номеру) — иначе в списке двоились бы строки. Полный набор связей виден в
  колонках «Ждёт»/«Откроет».
- CTE `ins` + `on conflict do nothing returning 1` отдаёт 0 строк при дубле —
  поэтому статус возвращаем отдельным `select`, а не по числу строк.
- Нельзя переименовывать SQL-файлы в «удобные»: `ns.bot.js` собирает путь как
  `sql/dev.nasushchnoe.<key>.sql`, ключи обязаны совпадать (`dep.list` и т.д.).

## 2026-10-21 — «насущное» в любом окончании (терпимо к голосу)

**Запрос:** «В ns.js код слушает насущное и добавляет насущное — надо, чтобы он
был не критичен к окончанию: насущное, насущную и т.д., потому что распознавание
голоса постоянно ставит женский род».

**Сделано:**
- `u-barn/ns.bot.js`: ключевое слово вынесено в константу
  `NAS = 'насу[щш]н(?:ое|ую|ого|ому|ым|ом|ая|ой|ые|ых|им|ем|ие|ия)'`, три
  регулярки собраны из неё (`RE_LIST`, `RE_ADD`, `RE_ADD_IN`) вместо литералов.
  Теперь «насущное/насущную/насущного/насущном/насущная/насущные» — одно и то же
  слово; плюс терпим «насушное» (щ/ш путает голос).
- Заодно закрыты фразы, которые раньше уходили в «не моё»: «насущное покажи»,
  «что в насущном», «в насущную: <дело>», «насущную: <дело>» (без «в»).
- Задеплой на прод: `git push` + `ssh ubarn171` → `git pull --ff-only` +
  `touch web.server.js` (nodemon рестартнул `crons.js`, процесс поднят).

**Грабли (важно):**
- `\b` в JS не видит кириллицу — границы слов в регулярках задаём явно
  (`\s`, `(?:\s|$)`), а не `\b`.
- Порядок правил важен: правило «покажи» (список) должно проверяться **до**
  правила «добавь», иначе «насущное покажи» записалось бы делом «покажи».
- Проверка разбора — без Telegram: `node -e "require('./ns.bot.js').interpret('...')"`.

**Не сделано (замечено):** в `u-sluxa4/assistant.py.txt` маршрутизация «навык …»
(`run_skill`) слова «насущное» вообще не знает — навык `skills/nasushchnoe`
работает только через Telegram-бота. Голосовой путь «подружка, навык насущное
покажи» не заработает, пока `run_skill` не будет знать это слово.

## 2026-10-18 — «Вода голосом» писала мусор из-за точки

**Что:** диктовка телефона кладёт точки как разделители разрядов («Вода 1.003 229.»).
В `crons.js` вырезались только пробелы → `1.003229.` → PostgreSQL молча принимал это
как дробь `1.003229` (а `1.003.229.` вообще отвергал, и запись терялась).
Плюс `ns.bot` отвечал подсказкой на любое чужое сообщение → флуд в личке.

**Решение:** в обработчике «Вода» оставляем только цифры (показания счётчика —
всегда целое), пустое число → отказ с подсказкой, успех → «💧 записал N».
`ns.bot` на чужой текст молчит (пишет только в лог сервера).
