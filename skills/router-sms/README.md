# SMS роутера ZTE → Telegram

`scripts/router_sms.py` один раз в день в полночь по времени production-сервера
читает **отдельные SMS** из API роутера (а не сгруппированные диалоги со страницы
`http://192.168.8.3/index.html#sms`). Выбираются только сообщения с флагом
`isNew`; каждое отправляется в тот же Telegram-чат, что и production-бот.
Отправка использует общий `tools/tg.py` с очередью на случай временного
отсутствия сети.

## Доступ и состояние

- Запускать только на production (`ENVIRONMENT=PROD`).
- Пароль роутера берётся из `/home/vao/u-barn/.env` (`ROUTER_PASSWORD`).
- Telegram-токен — `TG_PROD_TOKEN` (fallback `TG_TOKEN`) из того же `.env`;
  чат — `teleGa.PROD.channel` из `u-barn/vals.json`.
- В `state/router_sms.json` хранятся только ID уже отправленных SMS;
  содержимое и номера отправителей не сохраняются. Каталог `state/` исключён
  из git. Отдельная база данных для состояния не используется.
- Отправляются только SMS, которые роутер помечает непрочитанными (`isNew`).
  После успешной отправки (или постановки в Telegram-очередь) Device SMS
  помечаются прочитанными через API роутера. При ошибке отправки SMS остаётся
  непрочитанным и будет повторена; если не сработала отметка прочитанного,
  сохранённый ID не даст отправить её повторно.
- При переходе со старого формата состояния непрочитанные SMS отправляются;
  уже прочитанные сообщения не пересылаются.
- Лог cron: `skills/router-sms/router_sms.log`.

Скрипт использует Playwright из `/home/vao/u-barn/venv` и Telegram helper из
`tools/tg.py`; отдельный браузерный пакет или секреты в конфиге не нужны.
