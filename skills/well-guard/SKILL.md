# Well Guard — проверка колодца

Фоновый наблюдатель за колодцем (насосом). **С 19.10.2026 работает на проде
(192.168.88.171) в cron** (`*/30`), Python `scripts/well-guard.py`.

## Логика

Данные — устройство «Колодец» (`ar.src` i=11, колонка `power`: `on`/`off`),
их пишет iHost в `ar.vals`. Скрипт ходит в БД напрямую (`psql`), т.к.
`/getdots` не отдаёт текстовые колонки. Три условия:

1. **Не включался >= 6.5 ч** → «не включался уже N ч, последний запуск ...»
2. **Включён и работает >= 30 мин** → «насос работает уже N мин — не качает ли вхолостую»
3. **Нет данных с датчика >= 15 мин** (мёртв iHost/шлюз) → «проверка слепа»

Каждый алерт шлётся **один раз на состояние** (state-machine в `state.json`:
`alerted: null|off|on|stale`), до снятия условия. Если данные ожили — пометка
«нет данных» снимается сама.

## Файлы

| файл | назначение |
|------|-----------|
| `scripts/well-guard.py` | скрипт (Python 3, psql + urllib, без зависимостей) |
| `config.json` | chat_id, пороги, путь к .env, реквизиты БД (в .gitignore) |
| `state.json` | состояние (создаётся сам) |
| `well-guard.log` | журнал проверок |
| `cron.log` | stdout задачи из cron |

## Cron (прод)

```
*/30 * * * * /usr/bin/python3 /home/vao/u-girlfriend/skills/well-guard/scripts/well-guard.py >> /home/vao/u-girlfriend/skills/well-guard/cron.log 2>&1
```

## Заметки

- Токен бота берётся из `/home/vao/u-barn/.env` (`TG_PROD_TOKEN`), БД-пароль —
  оттуда же (`DB_PASSWORD`); свои секреты скрипт не хранит.
- **iHost (`192.168.88.104`) мёртв с 08.08.2026** — датчик колодца не шлёт данные,
  первый реальный запуск (19.10.2026) ушёл алертом «нет данных». Как только iHost
  оживёт, алерты вернутся к нормальной логике (on/off).
- Пороги — в `config.json`: `off_alert_hours`, `on_alert_minutes`, `stale_minutes`.
