# Проверка отопления (локальный мониторинг)

## Когда использовать
Пользователь просит проверить **отопление** (или другой датчик) на домашней
странице мониторинга устройства и узнать текущие значения / значения за
последние минуты. Примеры запросов:
- «проверь отопление»
- «что с отоплением сейчас?»
- «какие значения за последние 5 минут?»
- «открой http://192.168.88.171:90/graph.html и скажи значения»

## Быстрый путь
Запусти готовый скрипт из этой папки навыка:

```powershell
# по умолчанию — Отопление (температура ТЕПЛОНОСИТЕЛЯ), за 5 минут
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "scripts/heating.ps1" -Minutes 5

# через быстрый алиас
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "scripts/heating.ps1" -Preset "отопление" -Minutes 10

# список устройств и алиасов
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "scripts/heating.ps1" -List
```

Параметры:
- `-Preset` — быстрый алиас (см. таблицу ниже), задаёт устройство+колонку.
- `-Device` — часть имени устройства (регистр не важен). По умолчанию `Отопление`.
- `-Column` — колонка данных (по умолчанию `defcol` устройства).
- `-Minutes` — окно «назад», в минутах (по умолчанию `5`).
- `-Server` — адрес (по умолчанию `192.168.88.171:90`).
- `-List` — показать устройства и алиасы.

Скрипт печатает таблицу точек с единицами (°C/Вт/…), а также мин / макс /
текущее / изменение.

### ⚠️ Важное различие
- **`отопление`** (gr=16) — **температура ТЕПЛОНОСИТЕЛЯ** (подача в систему
  отопления). Именно это обычно имеют в виду под «отоплением».
- **`котельная`** (gr=5) / **`Котельная`** (gr=2) — температура **воздуха в
  котельной**, это другое.

Не путать эти датчики.

|-------|-----------|---------|--------------|

## Как это работает (API страницы)
Страница `graph.html` рисует график в Plotly из данных, которые сама
запрашивает. Нужно повторить те же запросы (это и есть исходные данные
графика, а не чтение картинки):

- `GET http://<server>/getdevs`
  → JSON-массив устройств `[{ "i": <id>, "sname": "<имя>", "defcol": "<колонка>", "dots": { "cols": [...] } }, ...]`.
- `GET http://<server>/getdots?gr=<id>&col=<колонка>&back=<минут>&gsCoef=100`
  → JSON-массив точек `[{ "ts": "YYYY-MM-DDTHH:MM:SS.000Z", "val": <число> }]`.

Выбор «из дропдауна» = найти устройство по `sname` в `/getdevs` и взять его `i`
(и `defcol` для колонки). Параметр `back` задаёт глубину в минутах.

## Как отвечать
1. Назови устройство и колонку (например `Отопление`, `cels` — температура °C).
2. Покажи последовательность значений за период и **последнее (текущее)** значение.
3. Отметь динамику (растёт / падает, на сколько за окно).
4. Скажи явно, что данные взяты из JSON-эндпоинта (исходные данные графика),
   а не считаны с изображения.

## Важно про время
Метки `ts` помечены `Z`, но идут по часам **устройства** и могут не совпадать с
локальным временем (устройство может не учитывать летнее время). Чтобы не
путать: показывай время как есть либо считай **относительные** минуты от
последней точки (как делает скрипт). При необходимости сверь смещение,
сравнив последнюю точку с текущим временем.

## Заметки по поддержке
- `scripts/heating.ps1` должен быть сохранён в **UTF-8 с BOM** — Windows
  PowerShell 5.1 иначе читает файл как ANSI и ломает кириллицу.
- В PowerShell 5.1 `Invoke-RestMethod` возвращает массив как один объект,
  поэтому **не** оборачивай его в `@()` при получении (иначе `$_.ts` станет
  массивом). Для подсчёта используй `@($dots).Count`.
- Даты: `ConvertFrom-Json`/`Invoke-RestMethod` отдают `ts` строкой вида
  `2026-10-09T12:37:48.000Z`; скрипт парсит её с `AdjustToUniversal` и выводит
  время как есть (без пересчёта пояса).
